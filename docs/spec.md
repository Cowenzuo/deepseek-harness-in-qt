# deepseek-harness 本地客户端外壳（dshinqt）规格说明（定版）

## 1. 概述

本工程为 [deepseek-harness](https://github.com/deepseek-ai/deepseek-harness)（`dsh`）套一层本地桌面外壳，提供启动、更新、Git 查看三类能力。dsh 自身业务配置（API key、模型等）由其 Web UI 承担，外壳不干预。

## 2. 核心功能

### 2.1 设置管理

- 入口：菜单栏「设置」，弹出设置对话框。
- 设置项：

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| 源码路径 | `D:\framework\deepseek-harness` | 启动时探测不到则进入「未配置」状态并提示 |
| 启动命令 | `pnpm dsh web` | 命令主体，**不含端口**（端口由端口字段自动追加） |
| Web UI 端口 | `3080` | 用于就绪轮询、页面加载与启动参数 |
| node 路径 | 空（从 PATH 查找） | 可显式指定 |
| pnpm 路径 | 空（从 PATH 查找） | 可显式指定 |

- 校验：源码路径须存在且为 dsh 仓库（含 `pnpm-workspace.yaml`）；端口取 1–65535。
- 持久化：JSON 文件，位于 `QStandardPaths::AppConfigLocation`；启动时读取，修改即写回。

### 2.2 启动管理

- 外壳启动时，若源码已配置，自动执行启动流程（无需手动点击）。
- 运行状态机：`未启动 → 启动中 → 运行中 → 停止中 → 已退出(异常)`。
- 启动前体检（任一不满足则提示，并提供「一键构建」入口执行 install + build）：
  1. node 存在且版本 ≥ 22.19（解析 `node -v`）
  2. pnpm 存在（解析 `pnpm -v`）
  3. 依赖已安装：源码根 `node_modules/` 存在
  4. 构建产物存在：前端 `apps/web/dist/` 与库产物 `packages/**/lib` 均存在
- 启动：以源码路径为工作目录，用 `QProcess` 执行 `启动命令 + --host 127.0.0.1 --port <端口>`。
- 就绪等待：轮询 `http://127.0.0.1:<端口>`，可访问后加载 Web UI；超时直接报错。
- 进程接管：捕获 stdout/stderr 输出到日志页；提供停止、重启；进程意外退出时弹提示。
- 页面加载失败（端口未通 / 端口被占等）：**直接报错，不自动处理**。

### 2.3 更新管理

- 入口：菜单栏「更新」。
- 前置检查：
  - dsh 运行中 → 自动停止（一键全自动，连停带起）。
  - 本地有未提交修改（`git status --porcelain` 非空）→ **拒绝更新**并提示。
- 目标选择：
  - 选分支：checkout 分支后 pull。
  - 选提交：弹出「选择提交」对话框，展示历史提交并支持按 hash / 提交消息关键字**搜索**，选中后 checkout（detached HEAD）。
- 更新流程（顺序执行，任一步失败即中止并展示错误日志）：
  1. `git fetch --all --prune`
  2. 切换到目标（分支或指定提交）
  3. `pnpm install`
  4. `pnpm run build`
  5. 重新启动 dsh
- 进度展示：整体进度条 + 分阶段标签（拉取 / 切换 / 装依赖 / 构建 / 启动），日志实时滚动。
- 失败处理：中止后续步骤，错误日志高亮。
- 更新成功后：自动刷新加载 Web UI。

### 2.4 Git 查看

- 分支列表：本地 + 远程分支，当前分支高亮，支持切换。
- 提交列表：当前分支 log，展示 hash、作者、时间、提交消息；**动态加载**（滚动到底自动加载更多，每批约 100 条）。
- 状态：`git status` 摘要（未提交修改、未跟踪文件）。
- fetch：手动按钮刷新远程信息；**启动时后台自动 fetch**，发现远程有新提交时提示「可更新」。

### 2.5 主窗口

- 顶部菜单栏：文件（退出）、仓库（分支/提交/状态/fetch）、更新、设置、帮助。
- 主区域采用 `QStackedWidget` 分页：
  - **主页**：`QWebEngineView` 充满，加载 `http://127.0.0.1:<端口>`（dsh Web UI）。
  - **日志页**：显示 dsh 进程输出与更新日志。
  - 通过菜单/工具栏在主页与日志页之间切换。
- 状态栏：显示 dsh 运行状态与当前分支。

## 3. 非功能性需求

- 跨平台：Windows / Linux / macOS。
- 不修改 dsh 源码，仅通过 git 与 pnpm 命令操作。
- 单实例：同一配置目录只允许一个外壳进程。

## 4. 技术要点

- 进程：`QProcess`；端口就绪：`QNetworkAccessManager` 轮询。
- 配置：`QJsonDocument` + `QStandardPaths`。
- Git 操作：subprocess 调系统 `git` 命令。
- 端口联动：命令主体不含端口，外壳自动追加 `--host 127.0.0.1 --port <端口>`（dsh `web` 子命令原生支持，默认 3080）。

## 5. 设计决策

| 议题 | 决策 |
| --- | --- |
| Git 操作 | subprocess 调系统 `git` 命令 |
| 选定提交交互 | 「选择提交」对话框 + 按 hash/消息搜索 |
| 体检缺失 | 提供「一键构建」（install + build）入口 |
| 日志展示 | `QStackedWidget` 日志页，主页为 dsh Web UI |
| 提交列表分页 | 动态加载（滚动加载更多，每批约 100 条） |
| 更新成功后 | 自动刷新加载 Web UI |
| 自动 fetch | 启动时后台自动 fetch，有新提交提示可更新 |
| 单实例 | 需要 |
| Web UI 加载失败 | 直接报错，不自动处理 |
| 端口联动 | 命令主体不含端口，自动追加 `--host` / `--port` |
| 外部浏览器入口 | 不需要 |
| 自动启动 | 需要，外壳启动时自动启动 dsh（已配置时） |
| 构建产物判断 | 前端 `apps/web/dist/` 与库产物 `packages/**/lib` 都检查 |
