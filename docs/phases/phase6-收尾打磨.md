# Phase 6 — 收尾打磨

## 目标

补齐非功能需求：单实例、启动自动 fetch 提示、状态栏信息、崩溃提示完善、跨平台验证。

## 前置条件

- Phase 5 完成。

## 任务清单

- [ ] 单实例：用 `QLockFile`（配置目录下锁文件）保证同一配置目录只允许一个外壳进程，重复启动则激活已有窗口并退出。
- [ ] 启动时后台自动 `fetch`，发现远程有新提交时提示「可更新」。
- [ ] 状态栏：显示 dsh 运行状态 + 当前分支。
- [ ] 崩溃提示完善：进程异常退出时弹窗，给出最后日志摘要。
- [ ] 跨平台构建验证：Windows 主验；Linux/macOS 至少编译通过（条件允许时运行验证）。
- [ ] 整体走查：菜单项与功能全部连通，设置持久化正确。

## 验收标准

- 重复启动时只保留一个实例。
- 启动后能自动 fetch 并提示是否有更新。
- 状态栏信息随运行状态/分支实时更新。
- Windows 下完整可用；其余平台可编译。

## 技术注意事项

- `QLockFile` 锁文件放在配置目录，失败即退出（`QLockFile::tryLock`）。
- 自动 fetch 放后台线程或异步执行，不阻塞窗口显示。
- 崩溃提示要区分「用户主动停止」与「异常退出」。

## 产出文件

- `src/main.cpp`（单实例入口逻辑）
- `src/mainwindow.h/.cpp`（状态栏、自动 fetch 集成）
- `src/process/dshprocessmanager.h/.cpp`（崩溃提示完善）
