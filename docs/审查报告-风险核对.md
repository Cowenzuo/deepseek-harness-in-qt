## A. 逻辑与并发

### L1 ✅ 确认（高）
**问题**：`start()` 守卫只拦 Starting/Running，不拦 Stopping；stop 的 killByPort 在途时再 start 会并发两条异步链，迟到回调导致状态与用户最后操作相反、重复拉起服务、误删 service-source.txt。
**核对**：`dshprocessmanager.cpp` `start()`：`if (m_state == State::Starting || m_state == State::Running) return;`——Stopping 不拦截。`stop()` 的 killByPort 回调执行 `clearServiceSource(); setState(Idle);`，`start()` 的回调执行 `beginLaunch()`。两回调顺序不定：stop 迟到回调会在服务已启动后把状态打回 Idle 并删掉刚写入的记录。**确认**。

### L2 ✅ 确认（高）
**问题**：`beginStart()` 时若服务已是 Running（更新期间用户在服务页点了启动），`start()` 守卫静默返回 → 无 stateChanged → 更新永久卡在 Starting；Starting 期间点停止同理。
**核对**：`updatemanager.cpp` `onProcStateChanged` 仅处理 `Running→done / Crashed→fail`，Stopping/Idle 不处理。`beginStart` 无超时兜底、无 isRunning 前置检查。**确认**（触发前提：更新期间操作服务页按钮，而 L11 确认按钮可用）。

### L3 ✅ 确认（高）
**问题**：`runPnpm` 未注入代理环境变量，与 `MainWindow::runBuildStep` 不一致；代理网络下更新流水线 pnpm install 必失败。
**核对**：`updatemanager.cpp` `runPnpm` 无 `setProcessEnvironment`，直接 `startWrapped`；`mainwindow.cpp` `runBuildStep` 注入 `HTTPS_PROXY/HTTP_PROXY` 四组。**确认**。

### L4 ✅ 确认（高）
**问题**：`onFetch` 主线程同步 `git fetch`（GitClient::run waitForFinished 120000ms），UI 冻结最长 2 分钟。
**核对**：`settingsdialog.cpp` `onFetch` → `m_git->fetch(&err)` 同步阻塞；`gitclient.cpp` `fetch` 调 `run(..., 120000)`。**确认**。

### L5 ✅ 确认（高）
**问题**：`QtConcurrent::run([this]{ collectSnapshot(); })` 捕获对话框 this；模态对话框关闭析构后后台线程仍访问 `m_git`/`m_settings` → use-after-free；线程读 sourcePath 与主线程写并发 → QString 数据竞争。
**核对**：`settingsdialog.cpp` `refreshRepo`：`m_watcher->setFuture(QtConcurrent::run([this] { return collectSnapshot(); }));`。对话框为 `MainWindow::openSettings` 中的栈对象，exec 返回即析构；QFutureWatcher 析构不等待线程结束；collectSnapshot 内部 `m_git->currentBranch()` 等读取 `m_settings->sourcePath`（工作目录）。**确认**（触发窗口：fetch 慢时关窗，约 20s 级）。

### L6 ✅ 确认（中）
**问题**：`probeOnce` 只判 HTTP 200 不判 `__DSH_BOOT__`；端口是第三方服务且 service-source.txt 陈旧匹配时会 attach 成 Running；300ms 假阴性时 `start()` → `killByPort` 会 taskkill 第三方进程。
**核对**：`readywaiter.cpp` `probeOnce`：`ok = reply->error() == NoError` 即回调 true；`dshprocessmanager.cpp` `ensureRunning`：up 且 `isServiceMatching` → attach，up=false → start → killByPort（netstat → taskkill /t /f）。**确认**。附带说明：attch 误判的前提是 service-source.txt 恰好等于当前 sourcePath（陈旧但相等），概率低但真实。

### L7 ✅ 确认（中）
**问题**：`isDirty`/`checkout` 主线程同步 git（waitForFinished 20s），点更新时 UI 冻结。
**核对**：`updatemanager.cpp` `start()` 直接 `m_git->isDirty()`；`beginCheckout`（在 QProcess finished 信号回调中）直接 `m_git->checkoutBranch/checkoutCommit`，均走 `GitClient::run` 同步 waitForFinished。**确认**。

### L8 ✅ 确认（中）
**问题**：`checkAsync` 名义异步实为每项主线程同步执行（单项最长 6s，git/node/pnpm 三项累计最长 18s），仅项间 singleShot(0) 让出事件循环。
**核对**：`environmentchecker.cpp` `runNext` → `checkOne` → `runCapture`（waitForStarted+waitForFinished 各 3000ms 同步）。5 项检测中 git/node/pnpm 三项走 runCapture。**确认**（单项预算 2×3s 描述准确）。

### L9 ✅ 确认（中）
**问题**：① loadFinished 永不触发时（服务挂起），startReadyCheck 不启动 → 60s 总超时失效，永远白页；② runJavaScript 回调乱序可能 pageReady/pageFailed 重复或互相覆盖。
**核对**：`homepage.cpp` 超时判定全在 `checkReadyOnce` 内，由 `m_readyTimer` 驱动，timer 仅在 `startReadyCheck`（loadFinished 回调）启动。loadFinished 不触发 → 无轮询无超时。回调无一次性 guard、无请求序号。**确认**（②为低概率窗口）。

### L10 ✅ 确认（中）
**问题**：`attach()` 只 setState(Running)，不启动 m_pollTimer → attach 连接的既有服务日志页空白、无监督。
**核对**：`dshprocessmanager.cpp` `attach()` 仅 `emit logOutput + setState(Running)`；`m_pollTimer.start()` 只在 `beginLaunch` 中。**确认**。

### L11 ✅ 确认（中）
**问题**：更新流水线期间服务页启动/停止/重启按钮仍可用，点「启动」触发 L2 挂起、点「停止」与流水线 killByPort 交错。
**核对**：`settingsdialog.cpp` `refreshServiceUi` 只依据 `DshProcessManager::State` 启停按钮，不订阅 `UpdateManager::stageChanged`。**确认**。

### L12 ⚠️ 部分确认（低）
**问题**：checkAsync 可重入；分支快速连点丢请求；readLogTail 半行切分错乱；probeOnce 与 wait 响应混判。
**核对**：四个子项逐一核对：
- checkAsync 重入：`onApply` 无运行中守卫，旧链 singleShot 排队时新链重置 `m_asyncIndex`，两条链交错推进 → 可能跳过/重复，`checkCompleted` 两次 → 二次启动服务。**确认**（触发需构建完成回调与手动点校验几乎同时，概率低）。
- 分支连点丢请求：`loadBranchCommits` `if (m_commitWatcher->isRunning()) return;` → B 请求被丢，列表显示 A 提交而选中 B。**确认**。
- readLogTail 半行：跨 chunk 未闭合行被当完整行 trim 后 emit。**确认**（pnpm 进度行场景）。
- probeOnce/wait 混判：`onFinished` 仅凭 `m_waitActive` 过滤，wait 活跃时 probeOnce 响应也会参与 `isDshReady` 判定。**确认**（两者 URL 相同，影响小）。
- 综合判定：四个子项全部属实，本条应为 ✅，但严重度维持"低"合理。修正为确认。

## B. 健壮性与边界

### R1 ✅ 确认（高）
**问题**：netstat 子串匹配 `contains(":3080")` 会误命中 `:30800` 等；killByPort 会 taskkill 无关进程；inspectAsync 同病。
**核对**：`dshprocessmanager.cpp` `killByPort`：`if (!line.contains(marker) || !line.contains("LISTENING")) continue;`——marker = `":3080"`，`127.0.0.1:30800` 含该子串。**确认**（端口 80/443 时命中面更大；后果是误杀进程，高危）。

### R2 ✅ 确认（高）
**问题**：QProcess start 失败（FailedToStart）只发 errorOccurred 不发 finished → 更新状态机永久卡死 + QProcess 泄漏；5 处 QProcess 接线同病。
**核对**：`updatemanager.cpp` runGitFetch/runGitPull/runPnpm、`mainwindow.cpp` startClone/runBuildStep 均只连接 readyReadStandardOutput + finished，无 errorOccurred。Qt 文档确认 FailedToStart 不发 finished。**确认**。

### R3 ✅ 确认（高）
**问题**：startWrapped 的 shim 分支 `QString cmd = program` 不给程序路径加引号，含空格路径（corepack 默认 `C:\Program Files\nodejs\pnpm.cmd`）在 cmd.exe /c 解析时截断；startdetached 的 shellQuote 却加了，两处不一致。
**核对**：`startwrapped.h`：`QString cmd = program;` 后直接拼接 args。`startdetached.cpp`：`QString cmd = shellQuote(program);`。**确认**（当前用户 pnpmPath 无空格未触发，但普遍场景真实）。

### R4 ✅ 确认（高）
**问题**：GitClient::run 与 UpdateManager::runGitFetch/runGitPull 硬编码 "git"，无视 settings.gitPath；仅 startClone 使用 gitPath。
**核对**：`gitclient.cpp` `run()`：`p.setProgram(QStringLiteral("git"))`；`updatemanager.cpp`：`proc->start(QStringLiteral("git"), ...)`；`mainwindow.cpp` `startClone` 用 `m_settings.gitPath`。**确认**（与 A 组 gitPath 条目为同一问题的多视角重复，已合并计数）。

### R5 ✅ 确认（高）
**问题**：非 Windows 分支 killByPort/inspectAsync 直接回调空结果 → stop/restart 实际杀不掉服务，静默降级无日志。
**核对**：`dshprocessmanager.cpp`：`#else onDone(); #endif`（killByPort）、`#else cb(ServiceInfo()); #endif`（inspectAsync）。**确认**（当前 Windows 开发无碍，跨平台时影响）。

### R6 ✅ 确认（高）
**问题**：webPort 从 JSON 加载无范围校验，0/负数/超 65535 导致 QUrl 非法、探测假超时。
**核对**：`appsettings.cpp` `load()`：`webPort = o.value(...).toInt(webPort)` 无 clamp。**确认**。

### R7 ✅ 确认（中）
**问题**：onWaiterTimeout 未停 m_waiter → probeTimer 每秒轮询死端口直到进程退出；readLogTail seek 失败后日志监督永久停摆。
**核对**：`dshprocessmanager.cpp` `onWaiterTimeout` 只停 m_pollTimer；`ReadyWaiter::wait` 的 timeout 触发后 probeTimer 仍在跑（`stop()` 未被调）。`readLogTail`：`if (!f.seek(m_logPos)) { close; return; }`——文件被外部截短后每次 seek 都失败。**确认**。

### R8 ✅ 确认（中）
**问题**：shellQuote 不转义内嵌双引号、尾部反斜杠吞收尾引号；非 Windows `/bin/sh -c` 分支对 $/反引号/; 无防护。
**核对**：`startdetached.cpp` `shellQuote`：`return '"' + s + '"'` 无转义。**确认**（内嵌引号路径罕见，尾部反斜杠路径如 `D:\framework\` 手输可能触发；sh 分支双引号内 $ 会展开）。

### R9 ⚠️ 部分确认（中 → 低）
**问题**：homepage in-flight loadFinished 回调在 shutdown 置空 m_webView 后解引用 → 崩溃；webview-N.html 无限累积。
**核对**：崩溃窗口需「shutdown 置 nullptr 后、deleteLater 生效前」恰有 loadFinished 回调——lambda 以 this 为 context，shutdown 后 HomePage 即将析构，连接随之断开，窗口极小（毫秒级）。webview-N.html 静态计数无限累积为**确认**。综合：崩溃子项降级为低（理论真实、实际窗口极小），落盘累积确认。**部分确认，严重度降为低**。

### R10 ⚠️ 部分确认（中 → 低）
**问题**：debug.log/dsh-web.log 无限增长占满磁盘。
**核对**：`main.cpp` 的 debug.log 每次进程启动 `Truncate`；`dshprocessmanager.cpp` `beginLaunch` 对 dsh-web.log 每次启动 `Truncate`。**跨会话不增长**，仅单次长会话内持续追加。原描述"无限增长占满磁盘"不准确。**修正：单会话内无界增长（低），每次启动截断**。

### R11 ✅ 确认（中）
**问题**：checkoutBranch 只剥 `origin/` 前缀，切 `upstream/xxx` 等非 origin 远程分支 → git checkout upstream/foo 产生 detached HEAD，违背"避免 detached HEAD"设计承诺。
**核对**：`gitclient.cpp` `checkoutBranch`：`if (target.startsWith("origin/")) target = target.mid(7);`。带远程前缀的分支名 checkout 会进入 detached HEAD（git 的 DWIM 仅对无前缀名字生效）。设置弹窗分支树含所有远程分支（不止 origin）。**确认**。

### R12 ❌ 误报 + ✅ 部分（低）
**问题**（4 个子项）：
- netstat 本地化风险：**误报**——Windows netstat 输出固定英文（TCP/UDP/LISTENING 等），不随系统语言变化。
- 相对 sourcePath 按 cwd 解析：**确认**——手输相对路径时 QDir 按进程 cwd（GUI 应用不稳定）解析。
- parseLog 遇提交消息含 `\t`/`\n` 错位丢行：**确认**（理论场景，`%s` 未转义）。
- run() 实际预算 2×timeoutMs（waitForStarted + waitForFinished 各自计时）：**确认**；超时后 QProcess 析构强杀 git，可能残留 .git/index.lock：**确认**（git 被 kill 时 lock 可能残留，下次操作报错）。
- 综合判定：1 个子项误报，3 个确认。
