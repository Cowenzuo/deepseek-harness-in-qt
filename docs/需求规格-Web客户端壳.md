# dshinqt 界面壳 v2 需求规格（Web 客户端形态）

> 状态：基线整理稿（2026-08-31）
> 来源：v1（Qt 壳）当前实现的功能全景，按**需求**（行为/规则/反馈）重述；
> 不含任何技术实现方案（承载技术栈、组件、信号等均不在此文档范围内）。
> 用途：作为以 Web 客户端技术重构界面壳的需求基线；实现方案另行评审。

---

## 1. 背景与目标

### 1.1 现状与动机

现有界面壳以桌面原生技术承载 dsh 的 Web UI，承担了"环境引导 + 服务编排 + 内嵌 Web 页面 + 工具链"四类职责。承载层的体验问题（页面认证适配、下载、剪贴板权限、就绪判定等需要壳侧大量特殊处理）是重构的直接动机。

### 1.2 目标

以 **Web 客户端形态**（与 VS Code 同源的底层 web 技术）重新实现界面壳，达成：

1. 功能基线 = 本规格第 2 章全部需求（现状能力不缺失）；
2. 承载体验与常规浏览器一致：认证、下载、剪贴板、页面加载不再依赖壳侧特判；
3. 保留服务常驻模型与全部工具链（构建自检、更新、会话修复等）。

### 1.3 边界

- 壳只做：环境引导、服务编排与监督、Web UI 承载、构建/更新/修复工具链、日志与状态呈现。
- **不做**：dsh 的业务配置（API key、模型等）管理——一律由 dsh 的 Web UI 承担，壳不干预。
- dsh 本体、git / node / pnpm 外部工具不变。

## 2. 功能需求

### A. 配置与持久化

**FR-1 配置文件**
- 配置持久化在程序目录内的配置文件中（绿色软件，随程序走）。
- 字段：源码路径、Web 端口、node 路径、pnpm 路径、git 路径、仓库地址、下载目录。
- 配置文件缺失/损坏 → 使用默认值继续运行；端口越界或非法 → 回退默认端口（3080）。
- 源码路径保存时统一转绝对路径（避免工作目录漂移导致相对路径失效）。

**FR-2 配置生效规则**
- 端口、源码路径变更：提示需重启服务才能生效，并提供一键重启（带确认）。
- 下载目录变更：即时生效，无需重启。

### B. 环境引导

**FR-3 环境自动探测**
- 启动时自动探测 node / pnpm / git 可执行程序；配置了显式路径则优先使用，未配置回退系统 PATH。

**FR-4 源码有效性判定**
- 以仓库标志文件（pnpm-workspace.yaml）判定源码路径是否有效。

**FR-5 引导流程**
- 环境或源码缺失时进入引导页：展示缺失项、允许补全路径（含目录选择）、重新校验。
- 校验通过后保存配置并继续服务启动流程。

### C. 服务生命周期（常驻模型）

**FR-6 服务启动**
- 以常驻后台方式启动 dsh 服务：启动即返回，不依赖壳进程存活；壳退出、重启均不中断服务。
- 启动过程不弹出无关窗口、不自动打开浏览器。

**FR-7 端口探测与连接（attach）**
- 启动前先探测端口：
  - 端口上已有服务且与当前源码路径匹配 → 直接连接（不重启服务）；
  - 已存在但不匹配 → 优先自动识别服务对应的源码路径并接管；识别失败才杀旧启新；
  - 端口空闲 → 启动新服务。

**FR-8 停止 / 重启**
- 停止：按端口清理服务进程树（异步完成），完成后回到未启动状态。
- 重启：杀旧启新，不经过中间空闲态；均有确认交互。

**FR-9 状态呈现与监督**
- 状态机：未启动 / 启动中 / 运行中 / 停止中 / 启动失败，状态实时呈现（状态栏）。
- 启动超时兜底（如 60 秒未就绪 → 判定失败并给出日志入口）。
- 服务日志持续滚动呈现（见 FR-24）。

**FR-10 就绪判定**
- 以"服务可达 + 页面呈现 dsh 特征"为就绪标准；就绪后加载页面。
- 判定必须适配服务认证要求（见 FR-12），不得把"需要认证"误判为"未就绪"或"无服务"。

### D. Web UI 承载

**FR-11 内嵌页面**
- 内嵌显示 dsh Web UI，窗口首帧即渲染（无白闪）；整体深色背景与界面一致。

**FR-12 服务认证（token）**
- 服务具备访问认证：无凭据访问被拒绝。
- 壳在启动/连接服务后**自动完成认证**：用户无需手动获取或输入任何认证信息。
- 认证会话应持久（服务重启后仍保持访问，无需重新认证）。
- 认证信息最小暴露：正常使用中不要求用户复制、粘贴或保存认证凭据。

**FR-13 页面就绪与容错**
- 以页面正面特征（聊天输入区/会话区挂载）判定界面可用，可用后才显示主页（避免露出加载中间态）。
- 超时未就绪 → 错误页（原因 + 重试入口）；重试为页面级重载。
- 单次加载允许一次自动重载自愈，不得无限循环。

**FR-14 下载**
- 页面发起的下载默认保存到系统下载目录；用户可在设置中指定下载目录。
- 配置的目录不可用时自动回退系统下载目录，并提示。
- 下载文件名为空时使用 URL 末段兜底。
- 下载开始 / 完成 / 失败均输出到日志页可见反馈。

**FR-15 剪贴板**
- 页面内的复制（及粘贴）功能可直接使用，无需用户额外授权或绕行操作。

**FR-16 页面权限策略**
- 除剪贴板等本地可信能力外，其余权限请求（摄像头、通知、定位等）默认拒绝并留痕。

### E. 构建与更新

**FR-17 一键构建**
- 流程：安装依赖 → 构建（产出 Web 包与库），步骤与实时输出在日志页呈现。
- 完成分派：引导页发起的构建 → 回到引导页重新校验；其余来源 → 直接启动服务。
- 失败：给出原因与日志入口，可重试。

**FR-18 克隆**
- 首次使用可克隆仓库到源码路径；克隆进度与失败原因可见。

**FR-19 启动前构建自检**
- 每次启动服务前自动判定构建产物是否过期：
  - 判据：仓库最新提交时间 vs 产物（apps/web/dist）生成时间；产物缺失或早于提交 → 过期。
  - 过期 → 提示"是否重新构建后启动"（默认建议重建）；确认 → 停止旧服务 → 日志页呈现构建 → 成功后自动启动服务；失败 → 错误页可重试。
  - 用户选择直接启动 → 尊重选择照常启动（风险自担）。
  - 无法判定（非 git 仓库 / 无提交信息 / 产物新鲜）→ 不打扰，直接启动。

**FR-20 更新管理**
- 更新前检查工作区脏状态：存在未提交修改 → 拒绝并说明。
- 支持按分支或指定提交切换（切换失败有明确文案，自动建分支兜底）。
- 流程：拉取远端 → 切换目标 → 合并更新 → 安装依赖 → 构建 → 重启服务；各阶段在界面呈现。
- 支持取消；重复触发有并发防护（进行中拒绝新请求并提示，不静默忽略）。
- 服务重启阶段有超时兜底（如 60 秒）。

### F. 会话修复

**FR-21 修复入口**
- 两处入口：设置「修复」页；状态栏快捷按钮（直达修复页）。

**FR-22 会话定位**
- 输入会话 GUID（支持短前缀），自动在本地会话数据目录中定位（跨项目目录搜索）。
- 唯一匹配才能继续；多匹配需提供更完整 GUID。

**FR-23 诊断（只读）**
- 报告目标会话各日志文件的健康状态：大小、事件数、异常类型与位置（记录行号、期望/实际序号、事件类型）。
- 识别加载器已隔离的损坏文件（.corrupt-*）与正常文件。

**FR-24 修复（安全规则）**
- 修复前自动备份（带时间戳的备份文件）。
- 按异常形态自动选择修复策略：
  - 序号重复 → 重复点之后全部记录序号顺延（事件零丢失）；
  - 序号重叠（崩溃恢复方合成的关闭事件与真实延续重叠）→ 丢弃合成块，保留真实延续；
  - 序号缺口 → 按可提交前缀截断（尾部引用缺失序号，不可恢复）。
- 修复结果经完整校验（全量序号连续 + 加载器语义）通过后才落盘；校验失败自动还原备份并报错。
- 主文件含有效事件时不得覆盖（修复结果另存并提示），避免数据丢失。
- **拒绝修复当前活动会话**（正在使用的会话），需先结束该会话。

**FR-25 修复反馈**
- 修复过程与结果（备份路径、策略、事件数、落盘路径）完整输出到页面内可见区域。

### G. 日志与状态

**FR-26 日志页**
- 聚合展示：服务输出、构建/克隆输出、环境体检、下载事件、修复输出。
- 错误行视觉区分；自动滚动跟随；行数上限（防内存无界增长）；一键清空；返回主页。

**FR-27 状态栏**
- 运行状态消息（dsh 运行状态 / 更新阶段 / 构建阶段）。
- 按钮组：设置、日志、刷新页面（快捷键 F5）、会话修复、打开 DeepSeek 开放平台（外开浏览器）。

**FR-28 页面刷新**
- 手动刷新 = 重新加载 Web UI 页面（保持认证可用），而不是重启服务。

### H. 设置界面

**FR-29 设置弹窗**
- 左侧导航 + 右侧页面；导航项：常规 / 服务 / 更新 / 修复 / 关于。
- 导航项为图标 + 文字形态，选中项有明确指示（高亮底 + 指示条）。

**FR-30 各页内容**
- 常规：源码路径、端口、node/pnpm/git 路径、仓库地址、下载目录（支持目录浏览选择）。
- 服务：服务状态展示、启动 / 停止 / 重启操作（带确认）。
- 更新：当前分支与同步状态、分支/提交列表与切换、拉取更新操作。
- 修复：GUID 输入、扫描诊断 / 修复 / 取消操作、输出区（FR-22~25）。
- 关于：名称、版本、功能说明、仓库链接。

**FR-31 页间协作**
- 保存配置前等待在途后台任务结束（避免并发读写）；保存成功后刷新关联页面数据。

### I. 错误与反馈

**FR-32 错误页**
- 启动受阻 / 页面加载失败时展示：原因说明 + 可用操作（重试 / 一键构建 / 查看日志）。

**FR-33 反馈即时性**
- 任何耗时操作（构建、克隆、更新、修复）触发瞬间即有文字反馈（做什么、当前阶段），不得出现"点击后长时间无任何提示"的状态。
- 操作被拒绝（如已有任务进行中）必须给出提示，不得静默忽略。

### J. 视觉与交互

**FR-34 深色主题**
- 全界面深色统一（窗口、组件、内嵌页面背景协调，无突兀亮色区域）。

**FR-35 图标体系**
- 功能图标使用统一线条风格；常态/激活（悬停/选中）双态视觉。

**FR-36 键盘可达**
- 常用操作有快捷键（如刷新 = F5）；焦点可键盘遍历（Tab）。

**FR-37 危险操作确认**
- 停止 / 重启服务、更新、修复、克隆等破坏性或耗时操作执行前需用户确认。

### K. 多实例与数据安全

**FR-38 多实例共存**
- 同一机器可同时运行多个壳实例（不同端口/源码），互不干扰；各实例独立数据目录。

**FR-39 会话数据安全**
- 壳退出、重启、崩溃均不得中断正在运行的服务与本地会话数据（DSH_HOME）。
- 修复工具（FR-24）对活动会话的拒绝是硬约束。

## 3. 非功能需求

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| NFR-1 | 启动时效 | 服务就绪 + 页面可用；超时（60 秒级）有明确失败反馈而非无限等待 |
| NFR-2 | 异步与并发 | 所有耗时操作异步执行不冻结界面；同一类任务单实例模型；迟到的过期回调不得影响新状态 |
| NFR-3 | 日志性能 | 持续运行下日志内存有上限；跨块半行正确拼接 |
| NFR-4 | 安全性 | 认证信息最小暴露；对外部命令（git/node/pnpm）路径可配置；修复操作对数据只增备份、不静默覆盖 |
| NFR-5 | 平台 | Windows 桌面；依赖 node / pnpm / git 外部工具 |
| NFR-6 | 可维护性 | 状态命名、URL 拼接、就绪/过期判定等规则单一数据源；纯逻辑可独立测试 |

## 4. 迁移动机对应的体验目标（承载层）

以下为本次重构在承载层必须**优于现状**的体验目标（现状依赖壳侧特判，重构后应与常规浏览器一致）：

1. 页面认证：无需任何壳侧特判或用户操作即可访问（现状需从服务日志提取凭据并注入）。
2. 下载与剪贴板：与浏览器一致地开箱可用（现状需壳侧权限承接）。
3. 页面就绪：可靠且无需"锚点轮询 / 自愈重载"类补偿机制。
4. 深色与字体渲染：与 Web 技术栈原生一致（现状需壳侧逐项调配）。

## 5. 明确不做（Out of Scope）

- dsh 业务配置管理（API key、模型、联网搜索等）——归 Web UI。
- DeepSeek 开放平台余额 / 用量 / 充值记录的 API 接入（已决策：仅提供一键打开平台网页入口）。
- 内嵌第三方登录页（开放平台登录走系统浏览器）。
- 移动端 / 非 Windows 平台（本版本）。
